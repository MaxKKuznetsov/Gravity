# Gravity — CLAUDE.md

2D-аркада в браузере: корабль (вид сверху) с инерцией летает вокруг планеты,
которая притягивает его и метеориты по закону всемирного тяготения (1/r²).
Учебный и развлекательный pet-проект владельца (Maksim). Он хорошо знает
Python, а TypeScript изучает по ходу проекта.

Репозиторий: https://github.com/MaxKKuznetsov/Gravity
Локальная папка: `~/projects/Gravity`
План работ: `PLAN.md`

## Правила работы (обязательно)

- Менять файлы можно **только внутри папки проекта** `~/projects/Gravity`.
  Другие папки и файлы на машине не трогать (в том числе глобальные конфиги,
  `~/.npmrc`, `~/.gitconfig`, другие проекты).
- **Перед установкой любого ПО спрашивать владельца.** Это касается
  системных пакетов, Node.js, глобальных npm-пакетов и **новых зависимостей
  в `package.json`**. `npm install` по уже согласованному `package.json`
  делать можно.
- Общение — по-русски. Идентификаторы в коде — по-английски, комментарии
  в коде — по-русски.
- Работать маленькими шагами, по этапам из `PLAN.md`. После этапа
  обновлять в нём статус.
- Когда в коде впервые появляется конструкция TypeScript, которой нет в
  Python (типы-объединения, `interface`, `readonly`, модули ES, `this`
  в колбэках и т.п.), коротко объяснять её, сравнивая с Python.
- Перед коммитом запускать `npm run check` (типы + линтер + тесты).
  Нельзя отключать или пропускать тесты, чтобы получить зелёный результат.
- Git: работа в отдельных ветках, изменения в `main` через pull request.
  Не переписывать историю `main`.

  движков: физика своя.
- Vitest — тесты физики и чистой логики.
- ESLint + Prettier — стиль.

## Структура (целевая)

```
src/
  main.ts          # точка входа: canvas, запуск игрового цикла
  core/            # игровой цикл, ввод, вектор Vec2, случайность
  physics/         # гравитация, интегратор, столкновения (без DOM!)
  entities/        # Ship, Planet, Meteor, Bullet
  game/            # правила: волны, очки, жизни, состояния игры
  render/          # отрисовка на Canvas, камера, HUD, частицы
  config.ts        # все настраиваемые константы игры
tests/             # тесты Vitest
```

`physics/` и `game/` не зависят от DOM и Canvas, поэтому их можно тестировать
в Node. Отрисовка только читает состояние и ничего в нём не меняет.

## Физика: соглашения

- Единицы: пиксели мира, секунды. Ось Y направлена вниз (как в Canvas),
  углы в радианах, по часовой стрелке от оси X.
- Гравитация: только от планеты (метеориты друг друга не притягивают).
  Ускорение `a = -G·M · r̂ / max(r, rMin)²`, где `r` — расстояние до центра
  планеты. Константы `G·M` и `rMin` лежат в `config.ts` и подбираются под
  масштаб экрана, а не берутся из реального мира.
- Фиксированный шаг симуляции (`DT = 1/120` с) с аккумулятором. Отрисовка
  идёт с частотой кадров браузера, физика от неё не зависит.
- Интегратор: semi-implicit (symplectic) Euler. Он сохраняет энергию на
  орбитах намного лучше явного Эйлера. Если понадобится, перейти на
  velocity Verlet.
- Масса метеорита влияет на столкновения, дробление и очки, но **не** на
  траекторию в поле планеты (ускорение не зависит от массы тела).
- Тест-эталон: круговая орбита со скоростью `v = √(GM/r)` за несколько
  оборотов должна сохранять радиус и полную энергию в пределах допуска.

## Геймплей: принятые решения

- Управление: A — поворот против часовой стрелки, D — по часовой
  (маневровые двигатели), W — тяга, мышь — прицел (не зависит от
  направления носа), ЛКМ — выстрел.
- Оружие реализует общий интерфейс `Weapon`, видов будет несколько.
  Пушка: скорость снаряда = скорость корабля + скорость выстрела в сторону
  прицела, дальше снаряд летит в поле гравитации планеты.
- Граница поля: корабль — мягкая (возвращающая сила + предупреждение),
  метеориты и снаряды за пределами круга поля удаляются. Телепорта с края
  на край нет.

## Стиль кода

- `strict: true`, без `any` (если без него никак — с комментарием почему).
- Векторы — маленький класс/набор функций `Vec2`, без внешних библиотек.
- Все «магические числа» (тяга, скорость поворота, G·M, скорость пуль) —
  в `config.ts`.
