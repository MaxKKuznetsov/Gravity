# Gravity — инструкции для Codex

## О проекте

2D-аркада в браузере: корабль с инерцией летает вокруг планеты, которая притягивает его и метеориты по закону всемирного тяготения (1/r²). Это учебный и развлекательный pet-проект Maksim. Владелец хорошо знает Python и изучает TypeScript по ходу проекта.

Репозиторий: https://github.com/MaxKKuznetsov/Gravity  
План работ и статусы: `PLAN.md`.

## Правила работы

- Работать только внутри папки проекта. Не менять глобальные настройки и другие проекты.
- Перед установкой ПО спрашивать владельца. Это относится к системным пакетам, Node.js, глобальным npm-пакетам и новым зависимостям. Установка уже согласованных зависимостей из `package.json` допустима.
- Общаться по-русски. Идентификаторы в коде писать по-английски, комментарии — по-русски.
- Следовать небольшим этапам из `PLAN.md`. После завершения этапа обновлять его статус и результат.
- Когда впервые используется конструкция TypeScript, незнакомая из Python (например, union-типы, `interface`, `readonly`, ES-модули или `this` в callback), кратко объяснять её через сравнение с Python.
- Перед коммитом запускать `npm run check` (типы, линтер, форматирование и тесты). Не отключать и не пропускать проверки, чтобы получить зелёный результат.
- Работать в отдельных git-ветках; изменения в `main` вносить через pull request. Не переписывать историю `main`.
- Не запускать проверки и тесты без запроса пользователя; если пользователь просит проверить изменения или готовится коммит, использовать `npm run check`.

## Стек и команды

- TypeScript (`strict: true`), Vite и чистый Canvas 2D. Игровые и физические движки не использовать: физика своя.
- Vitest для физики и чистой логики; ESLint и Prettier для стиля.
- Требуется Node 24 (`.nvmrc`). Перед npm-командами активировать nvm и выбрать версию проекта: `source ~/.nvm/nvm.sh && nvm use`.

```bash
npm run dev      # dev-сервер
npm run build    # production-сборка в dist/
npm run preview  # локальный просмотр сборки
npm test         # тесты Vitest
npm run check    # типы, линтер, форматирование и тесты
npm run format   # форматирование Prettier
```

## Архитектура

- `src/core/` — игровой цикл, ввод, векторы и случайность.
- `src/physics/` — гравитация, интегратор, столкновения и траектории; без DOM и Canvas.
- `src/entities/` — корабль, планета, метеориты и снаряды.
- `src/game/` — правила, волны, очки, жизни и состояние игры.
- `src/render/` — Canvas-отрисовка, камера и HUD. Отрисовка читает состояние и не меняет его.
- `src/config.ts` — настраиваемые игровые константы.
- `tests/` — тесты; `examples/` — склад примеров и референсов проекта:
  звуков, изображений, текстов и других материалов.

Физика и игровая логика должны оставаться отделены от DOM/Canvas, чтобы их можно было проверять в Node.

## Соглашения физики

- Единицы — пиксели мира и секунды; ось Y направлена вниз; углы в радианах, по часовой стрелке от оси X.
- Гравитация только от планеты: `a = -GM · r̂ / max(r, rMin)²`. Параметры `GM` и `rMin` подбираются под масштаб игры и находятся в конфигурации.
- Фиксированный шаг симуляции `DT = 1/120` с аккумулятором; частота отрисовки не влияет на физику.
- Используется semi-implicit (symplectic) Euler; он лучше сохраняет энергию орбит, чем явный Euler. При необходимости рассмотреть velocity Verlet.
- Масса метеорита влияет на столкновения, дробление и очки, но не на его ускорение в поле планеты.
- Эталон физики — круговая орбита со скоростью `v = √(GM/r)`, сохраняющая радиус и полную энергию в пределах допуска за несколько оборотов.

## Принятые решения по игре

- Цель — защищать планету. У планеты есть запас хитов; падение метеорита наносит урон по размеру. Проигрыш наступает при разрушении планеты или потере всех жизней корабля.
- Управление: A/D — поворот, W — тяга, мышь — прицел независимо от направления носа, ЛКМ — выстрел.
- Оружие реализует общий интерфейс `Weapon`. Скорость снаряда складывается из скорости корабля и скорости выстрела в направлении прицела; затем снаряд испытывает гравитацию планеты.
- Граница поля для корабля мягкая (возвращающая сила и предупреждение); метеориты и снаряды за её пределами удаляются. Телепортации через поле нет.
- Материалы из `examples/` не используются игрой напрямую. Перед использованием
  нужные файлы копировать в соответствующие рабочие папки проекта (например,
  игровые аудио — в `public/`).

## Стиль кода

- Сохранять `strict: true`; не использовать `any` без веской причины и поясняющего комментария.
- Векторы реализовывать небольшим `Vec2` или набором функций, без внешних библиотек.
- Игровые константы (тяга, скорости, `GM`, скорость пуль и т. п.) хранить в `src/config.ts`, не разбрасывать магические числа.
